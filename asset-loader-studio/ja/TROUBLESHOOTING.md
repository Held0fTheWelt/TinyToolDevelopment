# トラブルシューティング

## アセット不足

`/Game/Data/DA_Item.DA_Item` のように、オブジェクトサフィックスを含む完全なオブジェクトパスを使用してください。検証で `ALS.Table.MissingReferencedAsset` が報告された場合は、フィールドを既存のアセットにリターゲットするか、クリアしてください。

## 誤ったパス

`ALS.InvalidSoftObjectPath` および `ALS.Table.InvalidReferencePath` は、パスを Unreal オブジェクトパスとして解析できないことを意味します。Content Browser から参照を再度コピーしてください。

## 適用失敗

適用には、許可されたプレビューと承認トークンが必要です。エディターワークスペースでは、Apply ボタンが最後のプレビューを承認します。自動化を使用する場合は、`approval_token` にプレビュー ID または `approved` を設定してください。

## 権限拒否

アクティブなプロファイルを検査するには `asset_loader_studio.state.read.v1` を使用してください。よくある拒否の理由としては、読み取り専用モード、ドライラン専用モード、影響を受ける行/アセットの制限、`allowed_roots` 外のルート、または破壊的権限の不足が挙げられます。

## 保存失敗

一般的な適用処理はパッケージに変更フラグ（dirty）を立て、復旧ガイダンスを返します。変更されたアセットを確認後、Unreal エディターの保存ダイアログまたはソース管理ワークフローを通じて保存してください。

## 空行または重複行

空または重複した行 ID を持つ DataTable は、安定した行操作に安全にマッピングできません。所有するテーブル内の行の名前を変更または修復してから、新しいスナップショットを取得してください。

## 破壊的アクションのブロック

削除やその他の破壊的操作には、それを許可するプロファイルと明示的な破壊的承認トークンが必要です。計画をプレビューし、バックアップまたはソース管理ステータスを保存してから、確認済みのプレビューのみを適用することをお勧めします。
