# Asset Loader Studio ユーザーマニュアル

**Tiny Tools -> Asset Loader Studio -> Asset Loader Studio** からワークスペースを開きます。

Asset Loader Studio は、「検査」「検証」「プレビュー」「適用」「監査」という1つのレビューループを中心に構築されています。検査段階で停止することも、アクティブな権限プロファイルが許可している場合はガバナンスされた編集へと進むこともできます。

ワークスペースには7つのビューがあります：

- **Graph**: アセット、行、フィールド、参照、および診断ノードを表示します。
- **Table**: スキーマを認識した DataAsset/DataTable の行と編集可能なフィールドを表示します。
- **Validation**: 不足している参照、無効なパス、重複 ID、および権限ブロックについて説明します。
- **Jobs**: 最新のランタイムロードリクエストステータスを表示します。
- **Inspector**: アクティブモード、権限プロファイル、最後のプレビュー、および最後の適用レポートを表示します。
- **History**: 最近のワークスペースアクションを保持します。
- **Governance**: アクティブプロファイル、ルートオーバーライド、監査ステータス、プロファイルアクションを表示します。

モードによって変更権限が制御されます：

- **Simple**: 読み取り専用（read-only）プロファイルを使用します。
- **Guided**: 承認を得た安全な段階的編集を許可します。
- **Expert**: より広範な一括/永続化プレビューを許可しますが、適用前に引き続き承認が必要です。

`/Game/Data/DT_Items.DT_Items` などのフルオブジェクトパスを入力後、**Inspect** を使用します。行、フィールド、および新しい値の入力を使用して、構造化されたフィールド更新をプレビューします。**Apply** は最後に承認されたプレビューのみを実行し、変更されたパッケージに保存フラグ（dirty）を立てます。

## レビューループ

1. ソースアセットを検査します。
2. グラフ/テーブルの状態と診断情報メッセージを確認します。
3. 必要な権限範囲に一致するプロファイルを選択します。
4. 操作をプレビューし、ターゲット、プランハッシュ、影響を受ける数、リスク、および復旧ガイダンスを確認します。
5. 確認したばかりのプレビューのみを適用します。
6. 適用レポートと監査履歴を検査します。
7. レビュー後、変更されたパッケージを手動で保存します。
