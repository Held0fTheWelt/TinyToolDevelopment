# Technical Overview

This page gives maintainers and technical buyers a high-level view of how the plugin is organized.

For deeper code-level documentation, see [CodeDocumentation.md](CodeDocumentation.md). The main headers also include Doxygen-style comments for classes, structs, settings, and service APIs.

## Module

The plugin contains one editor module:

```text
CodeCopyrightEditor
```

It is an editor-only module. The plugin does not add runtime game code.

## Main Source Files

| File | Responsibility |
| --- | --- |
| `CodeCopyrightEditor.cpp` | Registers settings, tab spawner, and window menu entry. |
| `CodeCopyrightEditorSettings.h/.cpp` | Defines project editor settings and defaults. |
| `SCodeCopyrightEditorWidget.h/.cpp` | Tabbed Slate editor UI, workflow controls, preview, review list, and metadata editing. |
| `CodeCopyrightNoticeService.h/.cpp` | Template rendering, file scanning, notice matching, rewriting, JSON/SPDX/REUSE report generation. |
| `CodeCopyrightCheckCommandlet.h/.cpp` | Headless commandlet for local scripts and CI. |

## Editor Integration

The module registers:

- A Project Settings page under `Plugins > Code Copyright Editor`.
- A nomad tab named `Code Copyright Editor`.
- A menu entry under `Tools > Code Tools`.

## Data Flow

1. Settings define identity, license, templates, scope, protection, and behavior.
2. The UI or commandlet calls `ScanCodebase`.
3. The service collects files from scan roots.
4. The service filters by extension and exclusions.
5. Each file is analyzed.
6. Existing notice text is compared against the rendered template.
7. Own and protected markers decide whether rewriting is allowed.
8. Results are returned to the UI or commandlet.
9. Apply operations rewrite only selected/changeable files.
10. Reports are generated from the same result structure.

## Notice Rendering

Rendering uses `FCodeCopyrightRenderContext`, which contains:

- Owner and contact.
- Product/module/file values.
- Relative path.
- Per-file metadata.
- Year and license values.

The renderer replaces both `{Token}` and `${Token}` forms.

## File Safety

The scanner is conservative by design:

- Scan mode does not write.
- Protected notices are skipped.
- Conflict notices are skipped.
- Unsupported extensions are skipped.
- Excluded paths are skipped.
- Optional backups can be written before source rewrites.

## Commandlet

The commandlet class is:

```text
UCodeCopyrightCheckCommandlet
```

It supports:

- Scan-only CI checks.
- Optional fixing through `-Fix`.
- JSON, SPDX-style, and REUSE-style reports.
- Non-failing report mode through `-NoFail`.
- Strict protected notice policy through `-FailOnProtected`.

## Packaging

`Config/FilterPlugin.ini` includes buyer-facing documentation and release notes in packaged plugin builds:

```text
/Documentation/...
/CHANGELOG.md
```

This ensures buyers receive the guide, screenshots, CI workflow, and changelog without shipping extra helper scripts.

## Supported File Types

Default source extensions:

```text
.h
.hpp
.hh
.inl
.c
.cc
.cpp
.cxx
.cs
.usf
.ush
```

The list is configurable in Project Settings.

## Reports

Reports are generated by `FCodeCopyrightNoticeService`:

- `ToJsonReport`
- `BuildSpdxTagValueReport`
- `BuildReuseMarkdownReport`
- `WriteComplianceReports`

The SPDX-style report computes SHA1 checksums for files when possible.
