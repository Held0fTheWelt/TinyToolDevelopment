# トラブルシューティング

## セットアップのロード失敗

`Saved/UnrealCapabilityMesh/setup_validation_report.json` を確認してください。

一般的な原因:

- バンドル、有効化されたプラグイン、またはプロジェクトのセットアップルートに `project_profile.json` が存在しない
- 無効な `schema_version`
- マニフェストパスのタイポ
- 形式の崩れた JSON
- `capabilities` や `endpoints` などの必須配列の欠落

初回使用時、プロジェクトローカルのプロファイルはオプションです。UCM は、バンドルされたデフォルトプロファイルと有効化されたプラグインによって提供されるプロファイルを統合します。意図的なオーバーライドやプロジェクト所有のルートがある場合にのみプロジェクトプロファイルを作成し、`Reload Setup` をクリックしてください。

## 機能が検出されない

確認事項:

- 機能マニフェストが、その所有セットアップルート内のプロファイルから参照されているか
- 機能に空でない `capability_id` があるか
- エンドポイント ID が存在するか
- 必要なプラグイン名がロードされているか
- 必要なスキーマが存在するか

機能が別のプラグインに属している場合は、そのプラグインが有効になっており、そのパッケージに `Config/UnrealCapabilityMesh/project_profile.json` が含まれていることを確認してください。回避策としてプロバイダーの定義をプロジェクトにコピーしないでください。セットアップをリロードし、どのセットアップルートが検出されたかを確認してください。

## プロジェクトが重複定義の警告を報告する

プロバイダーが所有する同じ機能、エンドポイント、スキーマ、またはルートが、プラグインローカルのプロファイルとプロジェクトのオーバーライドの両方に存在する可能性があります。

プロジェクトがその定義を意図的にオーバーライドしている場合を除き、重複しているプロジェクト側のコピーを削除してください。プロジェクトプロファイルには通常、プロジェクト所有のポリシー変更や複合ルートを含めるべきであり、プロバイダーのコントラクトはプラグインローカルに保持します。

## 起動後に TTER が有効な UCM ルートを表示しない

オプションの Tiny Tool Execution Integration Bridge が有効になっていることを確認してください。その Editor モジュールは TTER の検出前に UCM セットアップをリロードします。新しいプロバイダーを有効にするかセットアップを編集した後は、`Reload Setup` をクリックしてツールの検出を更新してください。

## ルートがブロックされる

`Saved/UnrealCapabilityMesh/route_reports` 配下のルートレポートを開きます。ルートプランナーは説明とブロック理由を記録します。

一般的な原因:

- 集計された副作用を許可するルールがない
- ルートが `project_mutation` を使用しており、デフォルトルールがそれをブロックしている
- アセットの変更に承認またはドライランが必要である
- 入力スキーマと出力スキーマに互換性がない

Route Catalog の承認列またはプロファイルで **実験的** セルフ自動承認が有効になっている場合は、ガバナンス動作のトラブルシューティングを行う前に無効にしてください。広範なオーバーライドは、一致する Deny ルール、ルートのアセット/プロジェクト変更チェック、承認要件、およびドライラン要件をスキップするため、それらのポリシー結果を覆い隠してしまう可能性があります。

## エンドポイント呼び出しの失敗

`Saved/UnrealCapabilityMesh/invocation_reports` を確認してください。

一般的な原因:

- クラスパスが解決されない
- 関数名が誤っている
- パラメータバインディングが関数のパラメータと一致しない
- 呼び出しモードは宣言されているが、汎用呼び出し元がまだそれをサポートしていない
- プロバイダープラグインがロードされていない

## レポートが空である

再度 `Reload Setup` をクリックします。パネルはマニフェストをリロードし、診断を再生成します。また、プロジェクトの設定パスがエンジンやサンプルフォルダではなく、アクティブなプロジェクトであることを確認してください。

## ソース検証がハードコーディングを報告する

ソース検証により、UCM コード内のパートナープラグイン名や製品固有の機能 ID が報告されることがあります。C++ の分岐を追加する代わりに、統合固有の文字列をセットアップ JSON に移動してください。
