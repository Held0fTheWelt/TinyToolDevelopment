# Best Practices Journal ドキュメント

Best Practices Journal は、チームが Unreal Editor 内で再利用可能なエンジニアリングプラクティスを直接管理できるように支援します。プラクティスに関する知識、出所、レビュー状態、実装意図、および成果履歴を BPJ 所有のローカルアーティファクトルート配下に保存します。

バージョン 1.1.2 は Unreal Engine 5.4 以降をサポートしています。インポートされたエビデンスおよびプロバイダーの出力は、明示的に人間が昇格させるまでレビュー対象の候補にとどまります。外部の生成元がプラクティスを自律的に受容することはありません。

BPJ はスタンドアロンで動作します。オプションのエコシステムプロバイダーがエビデンス、候補、成果、またはハンドオフ先を提供できますが、ジャーナル、検証、検索、エクスポート、および成果ループは、すべてのオプションプロバイダーが存在しない場合でも引き続き使用可能でなければなりません。

## 主要概念

- プラクティス記録（Practice records）: 再利用可能なエンジニアリングガイドライン、コンテキスト、トレードオフ、適用可能性、失敗モード、およびレビュー状態を記述します。
- プラクティス候補（Practice candidates）: レビューが必要な下書きまたはプロバイダー由来の提案です。
- エビデンス記録（Evidence records）: プラクティスをプロジェクトローカルの証明、出所、権利メモ、および信頼度と関連付けます。
- アプリケーションブリーフ（Application briefs）: レビュー済みプラクティスを特定ターゲットに適合させるための意図を記述します。
- 成果インポート（Outcome imports）: 下流での作業によってプラクティスが検証、弱化、矛盾、特化、または置き換えられたかを記録します。
- 墨消し（リダクション）およびガードレールポリシー: 共有記録が意図的であることを維持します。
- ストレージバックエンド: BPJ を JSON アーティファクト、ローカル SQLite、または Postgres ベースのスタジオプロファイルとして実行できるようにします。

## 製品の境界

BPJ は、プラクティス記録、候補、エビデンス参照、レビュー状態、アプリケーションブリーフ、実装成果インポート、決定論的エクスポート、スキーマ検証、墨消し、ガードレール、およびローカルレポートを所有します。パッチ計画、ドライラン/適用（dry-run/apply）、ロールバック、最終的な実装検証、AI 実行、ソース/アセット変更の所有権は持ちません。

アプリケーションブリーフは意図専用のハンドオフアーティファクトです。下流のツールや人間のワークフローは、引き続き独自の計画、承認、変更、検証、およびロールバックの手順を実行する必要があります。

## 採択の契約

受容されたプラクティスは単なるスローガンであるべきではありません。採択や広範な再利用の前に、以下を記録してください：

- 問題、コンテキスト、および解決策。
- なぜ機能するのか、およびどこに適用されるのか。
- 前提条件、適合ルール、トレードオフ、および失敗モード。
- エビデンス参照、出所、権利メモ、および信頼度。
- レビュー状態、レビューアーメモ、および利用可能な場合は成果履歴。

不十分または欠落しているフィールドは、無害なフォーマットの問題ではなく、検証の指摘事項として扱う必要があります。

## ブリーフおよび成果の契約

アプリケーションブリーフには、プラクティスの識別情報、ターゲットコンテキスト、推奨される適合方法、制約、許可および禁止されるアクションカテゴリ、検証要件、期待される出力、エビデンス参照、承認状態、および互換性メモを含めることができます。コピーされた実装コードを含めたり、変更権限を付与したりしてはなりません。

成果インポートは履歴とプラクティスの信頼度を更新します。失敗または拒hされた成果は有用なデータです。元のプラクティスを弱めたり、矛盾させたり、特化させたり、置き換えたりする可能性があるため、非表示にするのではなくインポートする必要があります。

## ローカルアーティファクトとログ記録

BPJ は、`Saved/BestPracticesJournal/` 配下にプロジェクトローカルのアーティファクトを書き込みます。これには `practices`、`candidates`、`evidence`、`application_briefs`、`implementation_outcomes`、`reports`、`schemas`、`logs`、および `provider_inbox` が含まれます。Unreal の診断機能は `LogBestPracticesJournal` を使用します。耐久性のあるオペレーターエビデンスは、一時的なログ行からではなく、保存された JSON/Markdown アーティファクトから取得する必要があります。

## オペレーターサーフェス

- エディターワークベンチ: プラクティスの作成、レビュー、検索、ブリーフ作成、成果のインポート、および統合ステータスの検査。
- 保存済みアーティファクト: `Saved/BestPracticesJournal/` 配下の JSON/Markdown 記録。
- コマンドレット: 自動化およびリリースチェックのための検証、アーティファクトインポート、およびサンプルエクスポート。
- オプションのルート/プロバイダー: 初回利用の必須要件となってはならない、交換可能な統合サーフェス。

## ワークフロー

1. `Tools > Best Practices Journal` を開きます。
2. プラクティス記録を作成またはインポートします。
3. エビデンスとレビュー状態を添付します。
4. 採択前に記録を検証およびレビューします。
5. 実装コンテキストが判明している場合は、意図専用のアプリケーションブリーフを作成します。
6. 下流での作業完了後、成果をインポートします。
