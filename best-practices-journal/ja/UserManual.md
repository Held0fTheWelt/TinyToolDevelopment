# ユーザーマニュアル

Best Practices Journal は、エビデンスに基づくエンジニアリングプラクティスのガバナンスのためのエディターワークベンチです。意思決定支援およびレビューメモリであり、パッチプランナー、ソースエディター、AI 実行者、アセット変更ツールではありません。

## コアワークフロー

1. 手動メモ、エビデンス参照、またはオプションのプロバイダーからプラクティスまたは候補を取得します。
2. 適用可能性、トレードオフ、失敗モード、出所、権利メモ、およびレビューメタデータを追加します。
3. 受容またはエクスポートの前に記録を検証します。
4. タスクやレビューのガイドラインを選択する際にプラクティスを検索します。
5. レビュー済みのプラクティスまたは明示的な候補に対するアプリケーションブリーフを作成します。
6. 人間のワークフロー、UCI、PRS、またはその他の承認された実行者にブリーフを引き渡します。
7. 実装成果レポートをインポートして、プラクティスが検証、弱化、矛盾、特化、または置き換えられたかを記録します。

## プラクティス記録の品質

レビューに耐えうるプラクティスに BPJ を使用してください。有用な記録には以下が含まれます：

- 具体的な問題とターゲットコンテキスト。
- コピーされた実装コードではなく、再利用可能なガイドラインとして述べられた解決策。
- なぜガイドラインが機能するのか、どこに適用され、どこで失敗するのか。
- トレードオフ、前提条件、適合ルール、および失敗モード。
- エビデンス参照、出所、権利メモ、信頼度、およびレビュー状態。

これらのフィールドが不明な場合は、項目を候補または下書きのままにしてください。概要がもっともらしく聞こえるという理由だけで、受容されたガイドラインに昇格させないでください。

## パブリック操作

- **Create practice record**: エビデンス、コンテキスト、トレードオフ、およびレビュー状態を含む、レビュー済みまたは下書きのプラクティスを保存します。
- **Create practice candidate**: 明示的にレビューされるまで、下書きまたはプロバイダー由来の提案を保存します。
- **Attach evidence**: 制限された実装コードをコピーすることなく、ローカル/手動/プロバイダーの証明をリンクします。
- **Search practices**: BPJ 所有のアーティファクトストアから一致するプラクティス記録を返します。
- **Create application brief**: 特定のターゲットコンテキストに向けた意図専用のハンドオフをエクスポートします。
- **Import implementation outcome**: 実装または拒否の後にサイクルを完了します。

## アプリケーションブリーフ (Application Briefs)

ブリーフは、別のワークフローが安全に計画を立てられるよう支援するものであるべきです。ターゲットプロジェクト/モジュール/スコープ、推奨される適合方法、理由、制約、許可および禁止されるアクションカテゴリ、検証要件、期待される出力、エビデンス参照、承認状態、および互換性メモを含めることができます。

ブリーフは BPJ がファイルを変更するための許可として機能してはなりません。下流のツールが変更を適用する場合、そのツールがスコープ解決、ドライラン計画、承認、変更ゲート、検証、ロールバック、および独自の成果レポートを所有する必要があります。

## 成果インポート (Outcome Imports)

失敗、拒否、部分的な成功、および何も行わなかった（no-op）結果を含め、意味のあるすべての成果をインポートしてください。成果はプラクティスの履歴、信頼度、レビューメモ、および進化のリンクを更新します。元のプラクティスを普遍的に正しいものとして書き換えることはありません。

変更されたファイルの参照、検証レポートのパス、得られた教訓、推奨されるジャーナルの更新、警告、エラー、および外部の計画やレポートへのリンクには、成果フィールドを使用してください。

## オプションのプロバイダー

オプションのエビデンス、候補、成果、ハンドオフ、インデックス作成、ルート、または実装プロバイダーは、BPJ をより豊かにすることができます。これらは交換可能でなければなりません。プロバイダーが存在しない場合は、手動の記録、ローカルエビデンス、JSON/Markdown アーティファクト、および BPJ の検証を使用して続行してください。

## Capability Mesh (MCP)

ファイルアクセス権を持たないエージェントは、UMCP を介してレビュー優先のジャーナルライフサイクルを完了できます：

- `bpj.gather_candidates.v1`: プロバイダーの受信トレイフォルダ（PIO ハンドオフからの `project_intelligence_orchestrator` を含む）をスキャンします。
- `bpj.repository.list.v1`: プラクティス、候補、エビデンス、ブリーフ、および成果の ID を一覧表示します。
- `bpj.practice.read.v1`: シリアル化された1つの記録をインラインで読み込みます。
- `bpj.candidate.promote.v1`: レビュー済みの候補を昇格させます（ルート上でユーザー承認が必要です）。
- `bpj.import_artifacts.v1`: PIO 候補エンベロープ（`bpj.implementation_intent_candidates.` で始まる `schema` / `schema_version`）をインポートします。

プロバイダーの受信トレイパス: `Saved/BestPracticesJournal/provider_inbox/candidates/<provider_id>/`。

## コマンドレット

コマンドレットは検証、アーティファクトインポート、およびサンプルエクスポートに便利ですが、初回利用時の必須ステップではありません。自動化のための耐久性のある証明として、`Saved/BestPracticesJournal/reports/` 内の保存済みレポートを使用してください。ログは何が起こったかを要約します。保存されたアーティファクトが公式な記録として残ります。

## 境界

BPJ は知識と意図を記録します。ソースファイル、アセット、Build.cs ファイル、プロジェクト記述子、または外部プラグインコードを変更することはありません。下流の実行所有者は、独自のプレビュー、承認、検証、およびロールバックのゲートを実行する必要があります。

## ローカルエビデンスとログ

BPJ は耐久性のあるレビューエビデンスを `Saved/BestPracticesJournal/` 配下に保存します。ワークフローを共有または監査する際は、`reports`、`application_briefs`、`implementation_outcomes`、および `schemas` 内の JSON/Markdown ファイルを使用してください。Unreal ログカテゴリ `LogBestPracticesJournal` はオペレーターの診断とコマンドレットの要約用であり、受容されたプラクティスの公式な記録ではありません。
