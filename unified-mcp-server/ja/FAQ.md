# FAQ（よくある質問）

## このプラグインに AI モデルは含まれていますか？

いいえ。Unified MCP Server は接続インフラストラクチャです。プロバイダープラグインからのツールをローカル MCP クライアントに公開します。

## 独立した実行可能ファイルは含まれていますか？

いいえ。サーバーは Unreal Editor 内部で動作し、外部実行可能ファイルは同梱されていません。

## Node.js、Python、または mcp-remote は含まれていますか？

いいえ。Stdio 専用クライアントには `mcp-remote` などのユーザーがインストールしたブリッジが必要となる場合がありますが、これは同梱されていません。

## サーバーはデフォルトで有効になっていますか？

いいえ。デフォルトでオフになっており、Editor Settings で有効にするか、**Tiny Tools -> AI -> Universal MCP** から手動で起動する必要があります。

## ネットワーク上でリッスンしますか？

いいえ。`127.0.0.1` にのみバインドします。

## リクエストはどのように認証されますか？

サーバーは起動時にスコープ付き Bearer トークンを生成します。クライアントは `Saved/UnifiedMcpServer/agent/mcp_endpoint.json` からそれを読み取り、`Authorization` ヘッダーで 1 つのトークンを送信します。

## 複数のスコープ付きトークンをサポートしていますか？

はい。UMCP 1.0.5 は `default`、`read_only`、`automation`、および `experimental_admin` のセッショントークンをハンドシェイクファイルに書き出します。すべてのトークンは同じローカル `/mcp` エンドポイントを使用します。スコープにより、`tools/list` および `tools/call` に適用されるアクセスプロファイルが変更されます。

## ツールリストが空なのはなぜですか？

ベースサーバーはインフラストラクチャです。汎用の `mesh_*` プロバイダーを取得するには Unreal Capability Mesh を有効にするか、`IUmcpToolProvider` を登録する別のプラグインを有効にしてください。また、UMCP アクセス制御も確認してください。無効化されたプロバイダー、制限の厳しいプロファイル、アクティブな許可リスト、ブロックされたツールパターン、またはブロックされたツールグループは、意図的にツールを `tools/list` から非表示にできます。

## 特定のプロバイダーやツールを非表示にしたりブロックしたりできますか？

はい。UMCP は 1 つのローカルエンドポイントを保持し、ツールが MCP クライアントに到達する前にアクセス制御を適用します。プロバイダー ID の無効化、アクセスプロファイルの選択、完全一致またはワイルドカードのツール名やグループの許可/ブロックリストへの追加、または単一プロバイダーグループ用のコントロールパネルプロバイダー切り替えを使用できます。同じポリシーが `tools/list` と `tools/call` の両方に適用されます。

## セッション中に一時的にツールをブロックできますか？

はい。UMCP 1.0.6 はコントロールパネルおよび Blueprint 診断からのランタイム Access Guard ブロックを追加します。ランタイムブロックは、スコープ付きトークン用またはグローバルにツールを非表示にし、直接の呼び出しを `runtime_access_denied` で拒否し、サーバー停止時にクリアされます。

## アクセスジャーナルにはシークレットが保存されますか？

シークレットセーフな診断向けに設計されています。token、secret、password、API キー、authorization、bearer などのシークレットと思われる引数キーは、メモリ内および JSONL アクセスジャーナルから除外されます。伏字化された文字列およびサニタイズされた RAM エントリーは設定によって上限が設定されます。

## `mesh_configure_experimental_self_approval` とは何ですか？

**実験的（EXPERIMENTAL）**な自動自己承認用の Capability Mesh プロバイダーツールです。承認が必要な UCM ルートがグローバルまたはルート ID ごとに自動自己承認するかどうかを変更できます。有効化には `acknowledge_experimental_risk: true` が必要であり、自己責任のテストワークフロー専用です。

## 複数のプラグインでツールを追加できますか？

はい。任意のプラグインで `IUmcpToolProvider` を登録できます。ツール名にはプロバイダー ID の接頭辞が付きます。

## クライアントはツールのパラメーターとリスクを確認できますか？

はい。`tools/list` には各ツールの `inputSchema`、オプションの `outputSchema`、およびオプションのツール注釈が含まれます。UCM ルートツールは、ルートバインディング、スキーママニフェスト、ポリシー、および副作用からこれらを導出します。

## エディター内で接続されたツールを検査するにはどうすればよいですか？

**Tiny Tools -> AI -> Universal MCP -> Open Control Panel** を開きます。接続機能エリアはツールをプラグインごとにグループ化し、入力/出力スキーマの遅延展開をサポートし、訪問間で変更されていないメタデータをキャッシュします。UCM セットアップ変更後に完全な再ロードを強制するには **Refresh** をクリックします。

## プロバイダーが実行される前に UMCP がツールの引数を拒否したのはなぜですか？

`Validate Tool Arguments` 設定が有効になっています。この場合、UMCP は選択されたツールの `inputSchema` に対して着信引数をチェックし、必須フィールドの不足、許可されていない不明なフィールド、型の不一致、または Enum の不一致に対して `invalid_tool_arguments` を返します。

## どの Unreal Engine バージョンが対象ですか？

このプラグインは Unreal Engine 5.x コードプラグイン向けに作成されており、現在の UE 5.6 互換性のために C++20 を使用しています。

## これはパッケージ化されたゲーム（Packaged Games）向けですか？

いいえ。現在のサーバーはローカルツールおよびエージェント向けのエディターインフラストラクチャです。
