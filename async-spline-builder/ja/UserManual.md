# ユーザーマニュアル

このマニュアルでは、Unreal Editor での Async Spline Builder の使用方法と、主な機能の組み合わせについて説明します。

## 目的

Async Spline Builder は、編集可能なスプラインから生成コンポーネントを作成します。一般的な出力は、`USplineMeshComponent` セクションで作られた道路やトラックで、オプションの追加スプラインメッシュやプロシージャルウォールメッシュを備えています。

Actor は同期またはバッチでリビルドできます。バッチ処理により、長いトラックでもエディタの応答性が維持され、ランタイム時もネクストティックタイマーポンプを通じて利用可能です。

## 開くと有効化

1. **Edit > Plugins** を開きます。
2. **AsyncSplineBuilder** を有効にします。
3. プロンプトが表示されたらエディタを再起動します。
4. レベルを開くか作成します。
5. **Tools > Track Tools > Async Spline Builder** を開きます。

プラグインにはランタイムモジュールとエディタモジュールの両方が含まれています。Actor はランタイム対応です。ワークフローパネルとランドスケープ変形ツールはエディタ専用です。

## ワークフローパネル

Async Spline Builder パネルは、通常のトラックを構成するための推奨される方法です。通常のワークフローが複数の Details カテゴリに分散するのを防ぎます。

パネルはタブに整理されています:

- **Build**: Actor 選択、メッシュセットアップ、検証/ビルド/リビルド/キャンセル、非同期バッチ処理、閉ループ、デバッグポイントまたはセグメントラベル、オプションのレイアウトコネクタエンドポイントラベル。
- **Segments**: セグメントごとの `TrackSplineData`、セグメント行の作成、ジャンプギャップ、スタントドロップ。
- **Terrain**: ランドスケープスナップ、ランドスケープ割当、レイヤーペイント設定、高さ変形、加算レイヤーペイント、グランドウォール。

ワークフローパネルで意図的に重複していない高度な配列や珍しい設定には Details パネルを使用します。

## 基本的な Actor セットアップ

1. ワークフローパネルで **Create Actor** を押すか、既存の `ASplineGeneratingActor` を選択して **Use Selection** を押します。
2. **Setup** で `MainMesh` を割り当てます。
3. オプションで `StartMesh` と `EndMesh` を割り当てます。
4. ビューポートでスプラインポイントを移動します。
5. **Validate** を押します。
6. **Build Now** または **Rebuild** を押します。

`MainMesh` は必須です。既存の生成されたジオメトリがクリアされて何も置き換えられないことを防ぐため、検証により MainMesh なしのビルドはブロックされます。

## メッシュ作成時の考慮事項

道路メッシュは次を満たす必要があります:

- ローカル X 軸に沿ってタイル配置されること。
- メッシュの境界が道路の半幅を導出するために使用されるため、適切な Y 範囲を持つこと。
- 一貫したピボットを使用すること。
- コリジョンが必要でない限り、隠れたコリジョンの複雑さを避けること。

メッシュの境界が代表的でない場合は、`GroundWallSettings.TrackHalfWidth` を手動で設定します。

## スプラインの編集

標準の Unreal スプライン編集ツールを使用します。便利なフィールド:

- `bClosedLoop`: 最後のポイントを最初のポイントに接続します。
- `SplinePointType`: ポイント補間動作を制御します。
- `SplineZOffset`: スプラインコンポーネントを垂直方向にオフセットします。
- `bShowPointNumbers`: ポイントインデックスを表示します。
- `bShowSegmentNumbers`: セグメントインデックスを表示します。
- `bShowSplineVisualizationWidth`: より広いエディタスプラインを表示します。

ポイント番号とセグメント番号は生成されたデバッグコンポーネントであり、生成されたジオメトリに使用されるのと同じタグシステムによってクリーンアップされます。

## Track Shape Editor

Actor の生の受動的スプラインポイントのみを編集するのではなく、コンパクトなマルチレイアウト作成サーフェスが必要な場合は **Tools > Track Tools > Track Shape Editor** を開きます。エディタはネイティブな `track_shape.v1` ドキュメント上で動作し、コンパイルされたメイン、ピットロード、代替、またはサービスロードのレイアウトを選択した `ASplineGeneratingActor` に適用できます。

**Designer Tools** セクションは、日常の編集コントロールを提供します:

- ピットロード、代替、またはサービスロードのレイアウトを追加
- 選択した非メインレイアウトを複製または削除
- レイアウトの種類と閉ループ状態を変更
- 前または次のレイアウト、アンカー、またはセグメントを選択
- 選択したアンカーの X/Y 座標を編集
- 有効な最小アンカー数を維持しながらアンカーを追加、挿入、または削除
- 明示的なセグメントを追加または削除、選択したセグメントをラインとベジェの間で切り替え、または選択したレイアウトの連続セグメントを再構築

ビューポートは直接のアンカー選択とドラッグをサポートします。レイアウト一覧とインスペクタには同じ選択が反映され、JSON セクションではレビューやソース管理のために基礎となるドキュメントをインポートまたはエクスポートできます。

複雑な編集を適用する前に **Validate** を使用します。Apply は Actor の編集可能なスプライン/レイアウト状態を変更するため、ターゲット Actor を選択または作成した後にのみ **Apply** を使用します。

## ビルド

以下を使用します:

- **Build Now** / `BuildTrack`: 同期完全ビルド。
- **Rebuild** / `RebuildTrack`: `bUseAsyncBuild` が true の場合は非同期、それ以外は同期。
- **Cancel** / `CancelAsyncBuild`: アクティブまたは保留中の非同期ビルドをキャンセルします。

Actor は計算された `FTrackBuildPlan` からリビルドされます。プランは、生成が始まる前にセグメント範囲、ピース数、ドロップステータス、ジャンプギャップ、選択された道路メッシュ、追加メッシュ数を決定します。

## 非同期ビルド

設定:

- `bUseAsyncBuild`: バッチビルドを有効にします。
- `SegmentsPerTick`: ティックごとに処理される生成された道路/追加メッシュピースの数。
- `bAutoRebuildOnConstruction`: コンストラクションの変更が発生したときにリビルドをスケジュールします。

エディタワールドは、生成されたコンポーネントをクリアまたは準備する前にコンストラクションの変更をデバウンスするため、ポイントをドラッグしている間も既存のスプラインジオメトリを編集可能な状態に保ちます。ランタイムワールドはネクストティックタイマーポンプを使用します。両方のパスが同じピースレベルのビルダーを呼び出すため、1 つの長いスプラインセグメントがフレームを占pending することなく動作が整列したままになります。

## セグメントごとのデータ

`TrackSplineData` は各セグメントを構成します。スプラインセグメントよりもエントリが少ない場合は、インデックス `0` がフォールバックとして使用されます。

重要なフィールド:

- `RoadMesh`: オプションのセグメント固有の道路メッシュ。
- `MeshInstances`: セグメントの正確なメッシュピース数。
- `RoadMeshLength`: 希望する道路ピース長。
- `SegmentLength`: `RoadMeshLength` が未設定の場合のフォールバック間隔。
- `ExtraMeshStart`、`ExtraMesh`、`ExtraMeshEnd`: 追加のスプラインメッシュ。
- `ExtraMeshOffset`: 追加メッシュスロットの横方向オフセット。
- `GroundWallSettings`: セグメントごとのグランドウォールの挙動。

## 追加メッシュ

追加メッシュは、道路ピースと同じスプラインピース間隔に従います。ガードレール、縁石、フェンス、装飾的な側面オブジェクトに便利です。

開始、中間、終了の配列により、セグメントの境界で異なるメッシュを使用できます。追加メッシュには `AsyncSplineBuilder.RoadMesh` ではなく `AsyncSplineBuilder.ExtraMesh` のタグが付けられます。

## ギャップ

ポイントインデックス範囲の道路および追加メッシュ生成を抑制するには、`JumpGapsByPoints` にエントリを追加します。

範囲はセグメント範囲です:

```text
[StartPointIndex, EndPointIndex)
```

例えば、`StartPointIndex = 2`、`EndPointIndex = 4` はセグメント `2` と `3` を抑制します。

## ドロップ

セグメント範囲を下方または一定のワールド Z に移動するには、`StuntDropsByPoints` にエントリを追加します。

フィールド:

- `DropHeight`: 相対 Z オフセット。負の値は道路を下に移動します。
- `bUseConstantGapHeight`: オフセットの代わりに絶対ワールド Z を使用します。
- `ConstantGapWorldZ`: 有効時の絶対高さ。

ギャップのない 2 つの隣接するセグメントが異なる高さで接する場合、Actor はそれらの間にドロップウォールを作成します。

## グランドウォール

道路の端から下にプロシージャルウォールストリップを生成するには、`bGenerateGroundWalls` を有効にします。

グランドウォール:

- メッシュ派生またはオーバーライドされた道路幅を使用します。
- セグメントごとのウォール設定を尊重します。
- ジャンプギャップおよび無効なサンプルでストリップを分割します。
- 片面または両面にできます。
- 距離と実際の壁の高さに基づいた UV を使用します。

詳細なセットアップについては [LandscapeAndWalls.md](LandscapeAndWalls.md) を参照してください。

## ランドスケープスナップ

メッシュのスナップ:

- `bSnapMeshesToLandscape`
- `ObjectsToHitForLandscapeLineTrace`
- `LineTraceLength`

ポイントのスナップ:

- `bSnapPointsToLandscape`
- `bTangentPointsUpdate`

トレースクエリからヘルパーメッシュや一時オブジェクトを除外するには、`ActorsToIgnoreForGenerationTraces` を使用します。

## ランドスケープ変形

エディタ専用の変形は `DeformLandscapeNow` で実行されます。

要件:

- `Landscape` が割り当てられていること。
- 有効なスプライン。
- 適切な `FallOff` および `NumberOfSubdivisionsForDeform`。
- `bRaiseHeights` および/または `bLowerHeights` が有効であること。

高さ: `DeformLandscapeNow` またはパネルの **Deform Height**。レイヤーペイント: `PaintLayer` を割り当て、パネルで `PaintHalfWidth` / `PaintFallOff` を調整した後、`PaintLandscapeLayerNow` またはパネルの **Paint Layer** を実行します。ペイントは加算方式です。フォールオフを小さくしても、以前の広いバンドはクリアされません。`PaintFallOff = 0` はハードエッジになります。選択したレイヤー情報が `bNoWeightBlend` を使用している場合、他のランドスケープレイヤーが道路の下で減少することは保証されないため、パネル/検証で警告が表示されます。

## Details パネルを使用するタイミング

ワークフローパネルは意図的に絞り込まれています。以下を編集する必要がある場合は Details パネルを使用します:

- セグメントごとの `ExtraMeshStart`、`ExtraMesh`、`ExtraMeshEnd`、`ExtraMeshOffset` 配列
- トレース、UV、マテリアル、コリジョン、幅のオーバーライドを含む詳細な `FGroundWallSettings`
- ランドスケープスナップおよびウォール生成用のトレースオブジェクト配列
- スプラインポイントデータアセットの読み取り/書き込みフィールド
- 高度なデバッグおよびコンストラクション設定

## レイアウトコネクタ

Build タブには、パッシブなルートメタデータ用の **Layout Connectors** セクションが含まれています。コネクタは、ソースのレイアウト/距離をターゲットのレイアウト/距離にリンクし、`PitEntry`、`PitExit`、`Link`、`ServiceAccess` などの意味的種類を保存します。カスタム種類を入力することもできます。空でないカスタム種類は、エラーではなく警告として検証されます。

`Main` から最初のピットロードレイアウトへのデフォルトコネクタを追加するには **Pit Entry** を使用します。最初のピットロードレイアウトから `Main` に戻るデフォルトコネクタを追加するには **Pit Exit** を使用します。このセクションの **Validate** はコネクタ専用の検証を実行します。

コネクタの編集によって道路がリビルドされたり、生成されたジオメトリが削除されたりすることはありません。また、トランジションメッシュの自動作成、スプラインの切断、ピットロードへの地形変形の拡張、ピットロード専用レンダラーの有効化なども行われません。

有効なコネクタエンドポイントに視覚専用のテキストマーカーを配置するには、**Show Connector Debug** を有効にします。マーカーは、コネクタのインデックスと種類、`From` または `To` の役割、レイアウト ID、構成された距離を識別します。各エンドポイントは独立して解決されるため、一方の有効なエンドポイントがもう一方の無効な状態でも表示され続けることがあります。不足しているレイアウトやスプラインの範囲外の距離は無視されます。これらの問題の調査には **Validate** を使用してください。

マーカーは `UTextRenderComponent` デバッグ出力を使用し、道路、追加メッシュ、グランドウォール、ドロップウォールのジオメトリを追加しません。コネクタを編集すると、チェックボックスが有効な間マーカーが更新されます。**Show Connector Debug** を無効にすると、コネクタラベルのみが削除されます。これらのラベルの切り替えや更新によって、トラックがリビルドされたり、道路コンポーネント数が変更されたり、地形の挙動が拡張されたり、ビルド検証ゲートに影響したりすることはありません。

## データアセットワークフロー

`USplinePointListAsset` を `SplinePointList` に割り当てます。

以下を使用します:

- `WriteSplineToDataAsset`: 現在のスプラインポイントを保存します。
- `ReadSplineFromDataAsset`: スプラインポイントを読み込みます。

これは、生成されたコンポーネントとは別にトラックレイアウトを保持するのに便利です。

## 推奨されるプロダクションワークフロー

1. 短いテストスプラインを構築します。
2. 道路メッシュの境界とタイリングを検証します。
3. セグメントデータを追加します。
4. 追加メッシュを追加します。
5. ギャップとドロップを追加します。
6. グランドウォールのトレースを構成します。
7. 道路の形状が安定した後にのみランドスケープ変形を実行します。
8. リリース前に自動化テストを実行します。
9. PIE およびパッケージ化されたランタイムでレベルをテストします。

## プラグインがを行わないこと

- 置換/クリアまたはセグメントごとのランドスケープペイントモードは提供しません。
- メッシュの自動作成は行いません。
- すべてのランドスケープで完璧な地形ショルダーを保証するものではありません。
- コネクタのトランジション道路メッシュを自動生成することはありません。
- 最終的なトラック仕上げのための手動のアートディレクションに代わるものではありません。
