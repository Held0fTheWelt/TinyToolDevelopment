# FAQ（よくある質問）

## 初回用のセットアップウィザードはありますか？

はい。**Setup** タブには **Quick-Start** カードが含まれています。1 クリックで完全なモック、Ollama、または OpenAI/Anthropic クラウドスタック（プロバイダー、モデル、および `default` ルート）を作成し、接続テストを実行して準備状況を更新できます。以前に作成されたプロバイダーや、ユーザーが構成した `default` ルートを上書きすることはありません。

## LLM Store はチャットボットですか？

いいえ。LLM Store は、プロバイダー、モデル、ルート、ポリシー、シークレット、コスト追跡、およびエージェントのためのインフラストラクチャです。チャットボットやアセットアシスタントは LLM Store を利用できますが、独立したツールです。

## なぜモデル名ではなくルートを使用する必要があるのですか？

ルートにより機能コードが安定します。ツールが `docs.summarize` を呼び出す場合、チームはツールのコードを変更することなく、後から Ollama から llama.cpp や OpenAI へ切り替えることができます。

## すべてをローカルで実行できますか？

はい。`ollama`、`llamacpp`、`lmstudio`、`vllm`、`tgi`、または `mock` などのプロバイダーを使用し、ポリシーをローカル専用に設定し、ビルドルールを介してクラウドをブロックします。

## llama.cpp はサポートされていますか？

はい。`llamacpp` プロバイダータイプはローカルの llama.cpp サーバー向けです。典型的なベース URL は以下の通りです:

```text
http://localhost:8080
```

## API キーはプロジェクトファイルに保存されますか？

いいえ。`Config/LLMStore.json` にはプロバイダー、モデル、ルート、ポリシーが保存されますが、キーは保存されません。キーはシークレットストアまたは環境変数内に留まります。

## どのシークレットバックエンドを使用すべきですか？

単一開発者のセットアップでは、`EncryptedFile` がシンプルです。チーム向けには、Windows Credential Manager、macOS Keychain、1Password、または Azure Key Vault が通常最適な選択肢となります。

## Blueprint は C++ と同等のことができますか？

ユーザー向けの主な統合ポイントには Blueprint バージョンが存在します。これには、プロバイダー、埋め込み、ポリシー、テスト、コンテキストプロバイダー、エージェント、およびサブシステムファサード関数が含まれます。

## Codex、Claude、または Cursor を接続できますか？

はい、エージェントアドオン経由で接続できます。ストアは状態、認証ガイダンス、およびタスク実行を統一できます。具体的なツール統合はアダプターとして機能し、セキュリティルールに従う必要があります。

## LLM Store はシェルコマンドを自動実行しますか？

エージェントアダプターが実行を明示的に実装し、リクエストフラグがそれを許可している場合のみ実行します。`bAllowShellExecution`、`bAllowFileWrites`、および `bRequireDiffPreview` は、呼び出し元のセキュリティ要件を伝達します。

## コスト追跡はどの程度正確ですか？

精度はプロバイダーの利用データおよび構成された `CostRules` に依存します。プロバイダーがトークンカウントを返さない場合、ストアがトークンを推定します。請求においてはプロバイダーの課金データが一次情報となります。

## ローカルモデルにコストを割り当てることはできますか？

はい。ローカルモデルのコストを `0` に設定することも、1000 トークンあたりの概算 GPU コストなど内部的な会計値を設定することもできます。

## LLM Store に直接属さないものは何ですか？

アセット解説、Blueprint ドキュメント化、命名規則レビュー、プロジェクト RAG などの具体的な機能を持つツールは LLM Store を利用すべきですが、通常は別のプラグインやアドオンに配置されます。LLM Store 自体は自立しています。

## プロバイダーがオフラインの場合はどうなりますか？

ストアはプロバイダーのヘルス状態を更新し、フォールバックを試行し、監査ログにエラーを記録できます。サーキットブレーカー（circuit breaker）設定により、高コストまたはブロックされた繰り返し試行を防止します。

## CI で LLM Store を使用できますか？

はい。`LLMStoreCIPolicy` コマンドレットおよび自動化テストを使用します。GitHub Actions 用の例が `Documentation/CI` に含まれています。

## クラウドプロバイダーをライブでテストする必要がありますか？

必ずしも必要ではありません。リリース安全性の点では、モックテスト、構成検証、およびプロバイダーでのオプションの手動スモークテストで十分な場合が多くあります。クラウドでのテストは、意図的に構成されたシークレットがある場合にのみ実行する必要があります。

## どのファイルをリポジトリにコミットすべきですか？

コミット対象:

- `Config/LLMStore.json`
- オプションのプリセット
- 本番ルート用のチームドキュメント

コミット非対象:

- API キー
- ローカルシークレットファイル
- 機密性の高い運用データが含まれる場合のコスト元帳ファイル

## 完全な構成をエクスポートおよびインポートできますか？

はい。Governance タブでは、現在の構成を任意の JSON ファイルにエクスポートし、適用せずに JSON ファイルを検証し、検証が成功した場合のみ JSON 構成をインポートできます。エクスポートされた構成ファイルに API キーは含まれません。
