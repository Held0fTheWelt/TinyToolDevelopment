# トラブルシューティング

このガイドでは、LLM Store の構成、ランタイム、UI、ポリシー、およびビルドに関する一般的な問題について説明します。

## LLM Store のメニュー項目が表示されない

確認事項:

- プラグインが有効化されているか
- プラグイン有効化後にエディターを再起動したか
- `LLMStoreEditor` モジュールがビルドされているか
- クック済み（cooked）ランタイムビルドではなく Unreal Editor を実行しているか

予想される場所:

```text
Tiny Tools -> LLM Store
```

## プロバイダーに到達できない

確認事項:

- プロバイダーが有効化されているか
- ベース URL が正しいか
- ローカルサーバーが実行中か
- ファイアウォールやプロキシがリクエストをブロックしていないか
- タイムアウトが十分に長いか
- プロバイダータイプがサーバーと一致しているか

一般的なローカルのデフォルト値:

| プロバイダー | デフォルト |
| --- | --- |
| `ollama` | `http://127.0.0.1:11434` |
| `llamacpp` | `http://127.0.0.1:8080` |
| `lmstudio` | `http://127.0.0.1:1234/v1` |
| `vllm` | `http://127.0.0.1:8000/v1` |
| `tgi` | `http://127.0.0.1:8080/v1` |

最初に `Test Provider`、次に `Test Model`、最後に `Test Route` を試してください。

## ルートが解決しない

確認事項:

- ルートの `TaskKind` が要求通り正確に綴られているか
- ルートが有効化されているか
- 優先モデルが存在するか
- モデルが有効化されているか
- モデルが既存のプロバイダーを参照しているか
- プロバイダーが有効化されているか
- 必要に応じてクラウドキーが存在するか
- ルートポリシーがプロバイダータイプを許可しているか
- ビルド/ランタイムモードがルートを拒否していないか

`bUseMock` が有効な場合は、`MockModelId` が存在することを確認してください。

## API キーが欠落している

キーは `Config/LLMStore.json` には保存されません。

次のいずれかを使用してください:

- エディター内のプロバイダーキーフィールド
- 環境変数によるオーバーライド
- 構成されたシークレットバックエンド

環境変数のフォーマット:

```text
LLMSTORE_<PROVIDER_ID>_KEY
```

例:

```text
ProviderId: openai-main
Variable: LLMSTORE_OPENAI_MAIN_KEY
```

## 環境変数が無視される

確認事項:

- 変数名が正規化されたプロバイダー ID を使用しているか
- 設定後にエディタープロセスを再起動したか
- Unreal を起動するプロセスから変数が視認できるか
- 値に隠れたスペースが含まれていないか

Windows では、システム設定経由で環境変数を変更した場合、ランチャーやターミナルの再起動が必要になることがよくあります。

## Windows Credential Manager が機能しない

確認事項:

- Windows 上で実行しているか
- プラグインビルドから `Advapi32` がリンクされているか
- 資格情報ターゲット名が生成されたプロバイダーシークレット名と一致しているか
- ユーザーアカウントにアクセス権限があるか
- プロバイダー ID が変更されていないか

不明な場合は、一時的な環境変数を設定して、残りのプロバイダー構成を確認してください。

## macOS Keychain が機能しない

確認事項:

- `security` コマンドが使用可能か
- キーチェーンがロック解除されているか
- プロセスに項目の読み取り権限があるか
- 生成されたシークレット名が期待される値と一致しているか

## 1Password バックエンドが機能しない

確認事項:

- `op` CLI がインストールされているか
- 同じターミナルコンテキストで `op whoami` が成功するか
- `Vault` が設定されているか、または `SecretBackend.Meta` に完全な `op://...` 参照が含まれているか
- プロバイダー固有のオーバーライドが正しい項目とフィールドを指しているか

## Azure Key Vault バックエンドが機能しない

確認事項:

- `az` CLI がインストールされているか
- `az account show` が成功するか
- `Vault` が正しい Key Vault 名か
- 現在のアイデンティティにシークレットの get/set/delete 権限があるか
- プロバイダー固有のオーバーライドがシークレット名と一致しているか

## クラウドプロバイダーが失敗するがローカルプロバイダーは成功する

確認事項:

- API キーが存在するか
- ベース URL がプロバイダーのドキュメントと一致しているか
- プロバイダー側のモデル名が正しいか
- アカウントにモデルへのアクセス権があるか
- 組織のポリシーによってリクエストがブロックされていないか
- ルートのコストポリシーがリクエストを拒否していないか

プロバイダーのヘルス状態と最後の監査イベントを検査してください。

## llama.cpp が応答しない

確認事項:

- `llama-server` が実行中か
- ホストとポートが `BaseUrl` と一致しているか
- サーバーが OpenAI 互換エンドポイントを公開しているか
- モデルがロードされているか
- リクエストタイムアウトが十分に長いか

典型的な起動:

```text
llama-server -m C:\Models\model.gguf --host 127.0.0.1 --port 8080
```

プロバイダー:

```text
Type: llamacpp
BaseUrl: http://127.0.0.1:8080
```

## Ollama が応答しない

確認事項:

```text
ollama list
ollama serve
```

`FLLMModelConfig.Name` 内のモデルが Ollama 内に存在することを確認してください。

## 構造化 JSON が無効になる

確認事項:

- ルートが構造化出力に適したモデルを使用しているか
- ワークフローで必要な場合にモデルで `bStructured` が設定されているか
- 必要な場合のみ `FLLMStructuredOutputSpec.bRequireJson` が true になっているか
- スキーマが有効な JSON か
- プロンプトが JSON の周囲にプレーンテキストを要求していないか

一部のローカルモデルでは、有効な JSON を生成するために、より厳密なプロンプトが必要です。

## ツール呼び出し（Tool Calls）が欠落する

確認事項:

- プロバイダーがツール呼び出しをサポートしているか
- `FLLMToolSpec.ParametersJsonSchema` が有効か
- モデルがツールをサポートしているか
- プロバイダーアダプターがツール仕様をプロバイダーのネットワークフォーマットにマッピングしているか

## ストリーミングが 1 つのブロックのみを発行する

一部のプロバイダーはネイティブストリーミングをサポートしていないか、現在のアダプターが完全な応答しか解析できない場合があります。これは許容されています。ストリーミング API は単一の最終ブロックを発行するため、ユーザーは単一のコードパスを使用できます。

## コストが 0 と表示される

確認事項:

- コストルールが存在するか
- プロバイダータイプがルールと一致しているか
- モデル ID がルールと一致しているか、またはルールのモデル ID が空か
- プロバイダーが利用状況を報告しているか、またはトークン推定が有効か
- リクエストがゼロコストのローカルモデルによって完全に処理されていないか

## コストレポートが高すぎるように見える

確認事項:

- コスト単位が 1000 トークンあたりになっているか
- 入力値と出力値が反転していないか
- 通貨が一貫しているか
- モデル固有のルールがより一般的なルールと重複していないか
- プロバイダーの利用データがすでに別の単位で表現されていないか

## エージェントがインストールされていない

確認事項:

- CLI または IDE がインストールされているか
- ツールコマンドが `PATH` に存在するか
- ツールコマンドを視認できる環境から Unreal が起動されたか
- アダプターのヘルスチェックが正しいコマンド名を知っているか

セットアップ手順については `Authenticate...` ダイアログを使用してください。

## エージェントの認証が機能しない

以下を試してください:

1. `Copy Command` をクリックします。
2. 通常のターミナルでコマンドを実行します。
3. ログインを完了します。
4. Unreal を再起動するか、エージェントステータスを更新します。

LLM Store は資格情報を保存しません。外部ログインコマンドを表示およびコピーするだけです。

## エージェントがファイル書き込みを拒否する

`FLLMAgentRequest` を確認してください:

```text
bAllowFileWrites
bAllowShellExecution
bRequireDiffPreview
```

リクエストで許可されていない場合、アダプターは書き込みまたはシェルコマンドを拒否する必要があります。

## 出荷（Shipping）ポリシーが失敗する

確認事項:

- `Shipping` 用の `BuildRules`
- ルートのポリシー
- クラウドプロバイダーの使用状況
- ローカルまたはモックのフォールバックの利用可能性
- プロバイダーの許可リスト

コマンドレットをローカルで実行します:

```text
<UnrealEditorCommand> Project.uproject -run=LLMStoreCIPolicy -Config=Shipping -Unattended -NoSplash -NoSound
```

## 設定の状態が不透明

`Status` タブを開きます。プロバイダー、モデル、ルート、ブロック、警告、欠落しているキー、およびインベントリをまとめて表示します。

ステータスが古いように見える場合:

- 利用可能な場合は再読み込みをクリック
- タブを閉じて再オープン
- エディターを再起動
- `Config/LLMStore.json` が手動で変更されていないか確認

## Live Coding がアクティブなためビルドが失敗する

Unreal では、エディターの実行中に Live Coding が完全な外部ビルドをブロックすることがあります。コマンドラインから完全なビルドを実行する前に、エディターを閉じるか Live Coding を無効化してください。

これは通常の UI 使用には影響しませんが、CI タイプのビルドや UHT 検証をブロックする可能性があります。
