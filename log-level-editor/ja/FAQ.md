# FAQ（よくある質問）

## LogLevelEditor は C++ のログカテゴリ宣言を変更しますか？

いいえ。ソースコードを書き換えることはありません。カテゴリを発見し、Unreal のコンソールコマンドシステムを使用してアクティブな詳細度を変更します。

## 変更は永久的ですか？

設定された `ULogLevelDataAsset` に保存された意図的なオーバーライドのみが永続的です。DataAsset の更新を伴わないランタイムコンソール変更は一時的です。

## リストからカテゴリが消えたのはなぜですか？

永久非表示リスト、一時非表示リスト、検索テキストのフィルタリング、または現在のスキャン範囲に含まれていない可能性があります。

## デフォルトレベルが不足しているのはなぜですか？

スキャナーは一般的な Unreal マクロを認識します。プロジェクトがカスタムラッパーマクロや非常に特殊なフォーマットを使用している場合、カテゴリは発見されてもデフォルトレベルを推測できない場合があります。

## エンジンのログカテゴリを含めることはできますか？

はい。設定でエンジンプラグインおよび/またはエンジンソースのスキャンを有効にしてください。

## これはパッケージ化されたゲームで動作しますか？

いいえ。LogLevelEditor は開発ワークフロー向けのエディタプラグインです。

## ログ設定をチームと共有できますか？

はい。意図したオーバーライドを DataAsset に保存し、プロジェクトと共にバージョン管理してください。

## プラグインが起動時に保存されたレベルの適用を再試行するのはなぜですか？

Unreal エディタモジュールは、エンジンがコンソールコマンドを処理できるようになる前に起動する場合があります。再試行ロジックにより、起動初期における保存されたオーバーライドの消失を防ぎます。

## コンソールコマンドが失敗した場合はどうなりますか？

UI と DataAsset は、コマンドが成功したかのように更新されることはありません。失敗はログに記録されます。

## カテゴリを完全に消音することはできますか？

`NoLogging` を使用します。ただし、Unreal のコンパイル時詳細度およびランタイム詳細度のルールが適用されることに注意してください。

## カスタムの詳細度名をサポートしていますか？

いいえ。Unreal の標準的な詳細度名をサポートしています。

## DataAsset は必須ですか？

UI はランタイム変更の検査と適用を行えますが、起動時の永続的な再適用には設定された DataAsset が必要です。

## プラグインからのカテゴリを検出できますか？

はい。プロジェクトプラグインは通常のスキャンパスに含まれます。エンジンプラグインはオプションです。

## ソースコントロールで安全に使用できますか？

はい、意図して使用すれば安全です。主な共有アセットは永続オーバーライドを含む DataAsset です。
