# FAQ（常见问题）

本 FAQ 旨在同时服务于买家和技术支持。它解答了用户在购买前、首次设置期间以及在实际项目中验证恢复行为时可能会提出的问题。

## 快速解答

### 什么是 Lightweight Editor Mode？

Lightweight Editor Mode 是一款 Unreal Editor 插件，可通过可配置的配置文件临时降低编辑器视口渲染开销。旨在使重型场景的编辑更加流畅。

### 这是运行时优化插件吗？

不是。这是一个编辑器工作流工具。它不会优化打包后的游戏，也不会替代运行时性能分析或内容优化。

### 它会影响打包后的构建吗？

不会。该插件仅限于编辑器使用。它会在您于 Unreal Editor 中工作时更改编辑器会话状态，对打包后的构建没有任何影响。

### 它会永久更改我的项目吗？

不会。该模式被设计为临时叠加层。它会备份所更改的值，并在禁用时进行恢复。配置文件设置会作为编辑器用户设置保存，但关卡地图、资产和项目渲染器设置不会被正常启用/禁用流程重写。

### 它适合谁？

适用于在昂贵的编辑器场景中工作的 Unreal 用户：大型世界、高密度环境地图、大量使用 Lumen 的场景、浓雾关卡、大量植被刷拾或编辑器视口在日常工作中卡顿的项目。

## 功能与行为

### 启用时插件可以更改哪些内容？

根据所选的配置文件，它可以：

- 降低编辑器视口屏幕百分比。
- 降低整体可伸缩性质量。
- 禁用 Lumen 漫反射间接光照。
- 禁用 Lumen 反射。
- 禁用虚拟阴影贴图。
- 禁用体积雾和常规雾。
- 强制编辑器视口进入 Unlit 模式。
- 禁用编辑器视口中的实时渲染。

### 为什么启用时视口看起来效果变差了？

这是完全符合预期的。插件以视觉精细度换取编辑器的响应速度。请在编辑布局、结构、放置或 Blueprint 逻辑时使用它。在进行最终光照、材质、截屏、影视或视觉审核时将其禁用。

### 为什么视口会变成 Unlit（无光照）？

某些配置文件强制使用 Unlit，因为光照可能是编辑器视口渲染中最昂贵的开销之一。如果您仍需要光照上下文，可以编辑任何配置文件并关闭 bForceUnlitViewports。

### 为什么实时渲染会关闭？

某些配置文件会禁用视口实时渲染，以便视口停止连续重绘。这有助于缓解重型场景、笔记本电脑和散热受限机器的压力。您可以按配置文件禁用此行为。

### 它会禁用 Nanite 吗？

不会。插件不会直接禁用 Nanite。它专注于编辑器视口屏幕百分比、可伸缩性、Lumen、虚拟阴影、雾、视图模式和实时视口行为。

### 它会替代 Unreal 可伸缩性设置吗？

不会。它将可伸缩性作为更广泛的编辑器工作流的一部分。仅靠 Unreal 可伸缩性并不能覆盖每个编辑器视口开销，因此插件还控制特定于编辑器的视口屏幕百分比、选定的渲染器 CVar、视图模式和实时渲染行为。

## 配置文件

### 包含哪些配置文件？

插件包含四个可编辑的配置文件：

- Mild
- Balanced
- Aggressive
- Extreme

Balanced 是推荐的起始配置。

### 我可以自定义配置文件吗？

可以。打开 Project Settings > Plugins > Lightweight Editor Mode。每个配置文件都有自己的质量、屏幕百分比、功能开关和视口行为。

### 我可以在模式启用时更改配置文件吗？

可以。插件会立即刷新活动设置，并保留开启模式之前的原始备份。禁用时仍将恢复到开启模式前的状态，而不是中间的配置文件。

### 我应该使用哪个配置文件？

当您仍需要视觉上下文时使用 Mild。通用编辑使用 Balanced。重型布局、植被或世界编辑使用 Aggressive。当您需要极致响应速度且不在意画面精细度时使用 Extreme。

## 恢复与安全

### 禁用模式时会恢复什么？

在同一个编辑器会话期间，插件恢复：

- 备份的可伸缩性质量级别。
- 备份的 CVar 值。
- 由插件更改的视口视图模式。
- 由插件更改的视口实时状态。

### 如果在模式启用时关闭编辑器会发生什么？

模块的正常关闭会尝试禁用该模式。如果编辑器崩溃或意外终止，内存备份将会丢失。插件存储了一个备用视图模式，以避免在重启后卡在 Unlit 中，但在意外关闭后无法重建每个仅限单次会话的值。

### 如果重启后视口保持 Unlit 状态怎么办？

打开 Lightweight Editor Mode 窗口并点击 Disable Lightweight Mode。如果会话备份不可用，插件将使用存储的备用视图模式，并将 Unlit 视口移回合理的非 Unlit 模式。如有需要，您也可以从视口菜单手动将视口切换回 Lit。

### 其他插件可以重写相同的 CVar 吗？

可以。Unreal CVar 可以通过项目配置、命令行、设备配置文件、可伸缩性、插件和运行时编辑器代码进行更改。Lightweight Editor Mode 使用插件优先级标记的 CVar 写入并恢复自己的备份，但另一个系统随后的写入仍可能会胜出。

### 为什么缺失的 CVar 不被视为错误？

渲染器功能因引擎版本、项目设置、平台和自定义引擎分支而异。如果某个 CVar 不存在，插件会跳过它并记录日志，而不是让整个模式失败。

## 兼容性

### 支持哪个 Unreal Engine 版本？

实现目标针对 Unreal Engine 5.4 风格的编辑器 API 和渲染器 CVar。验证您打算列为支持的每个引擎版本，特别是较新的版本（渲染器 CVar 可能会发生变化）。

### 它适用于自定义引擎分支吗？

当所需的编辑器 API 和 CVar 存在时，它应该可以工作。如果自定义分支重命名或删除了渲染器 CVar，这些特定开关可能会被跳过。详情请检查 Output Log。

### 它适用于 Windows、Linux 和 Mac 吗？

该插件纯粹由编辑器 C++ 源码组成，避免了特定平台的运行时代码。在声称对该平台提供官方支持之前，仍应构建和测试每个目标编辑器平台。

### 它可以在 commandlet 中运行吗？

没有为 commandlet 提供有意义的工作流。主要行为依赖于交互式编辑器视口客户端、Slate UI 和编辑器会话状态。

## 工作流

### 如何打开它？

在 Unreal Editor 中使用 Tools > Performance > Lightweight Editor Mode。

### 如何自动启用它？

在插件窗口中勾选 Enable on Editor startup。插件会一直等待到编辑器视口存在，然后应用当前配置文件。

### 为什么启动自动启用在应用前需要等待？

在模块早期启动期间，Unreal 可能尚未创建编辑器视口客户端。插件使用一个短定时器，并在编辑器视口可用后启用该模式，从而可以可靠地捕获和更改视口状态。

### 我应该整天开启它吗？

可以，但最佳习惯是开启它以提高响应速度，并在进行视觉决策之前将其禁用。当模式激活时，请勿评估最终的光照、阴影、雾、材质或截屏。

### 如果我的瓶颈是 Shader 编译或版本控制，它有帮助吗？

没有。插件专门解决编辑器视口渲染开销。它不会解决 Shader 编译、资产加载、版本控制延迟、慢速磁盘、杀毒软件扫描或重型自定义编辑器工具的问题。

## 技术支持

### 支持请求中应包含哪些内容？

请包含：

- Unreal Engine 版本。
- 操作系统。
- 引擎是官方原生版还是自定义分支。
- 所选配置文件。
- 问题是发生在启用、切换配置文件、禁用、启动还是重启后。
- 包含 "[Lightweight]" 的 Output Log 日志行。
- 更改渲染器 CVar 的任何其他插件或脚本。

### 我在哪里可以检查插件做了什么？

打开 Unreal 的 Output Log 并搜索：

- [Lightweight]
- Backup CVar
- Restore CVar
- ApplyActiveSettings
- ApplyViewportSettings
- Lightweight mode ENABLED
- Lightweight mode DISABLED

### 最重要的一条使用规则是什么？

使用 Lightweight Editor Mode 换取编辑速度。禁用它以获取真实的视觉效果。
